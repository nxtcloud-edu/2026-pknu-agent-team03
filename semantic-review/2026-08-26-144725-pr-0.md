# APP-05~APP-09 pure-domain implementation

The new Java domain module establishes the interval, Context analysis, metrics, recovery, fake-port, and PowerShell execution boundaries for APP-05~APP-09. **Watch for:** **confirmed** Gate 2 blockers remain: most approved APP-05~APP-09 command behavior is not implemented, duration ratios discard sub-millisecond time, and the runner omits mandatory approved regressions.

**Verdict**: NEEDS_CHANGES

## High-level view

The module provides immutable records and calculation engines, but it stops short of the approved command responsibilities that turn validation rules into APP-05 through APP-09 domain behavior. There is no pure-domain path for App classification changes, Activity changes, Context confirmation/revision persistence, Baseline observation lifecycle, timer start, or manual recovery recording; these are not external Android/DB/UI concerns.

Recovery and Goal ratio components are derived with `Duration.toMillis()`, so a valid Java `Duration` with nanosecond precision produces a lower ratio than the actual elapsed time.

The approved quality design requires named coverage for remaining pure-domain boundary and failure behavior. The present 11-test run therefore cannot satisfy the selected Gate 2 verification scope.

## APP-05 through APP-09 commands stop at values and calculations

**confirmed** — `DomainTypes.java` validates records such as `AppProfile`, `ActivityRecord`, `ContextRevision`, `Goal`, and `RecoveredTime`, while the engines only analyze or calculate supplied values. The approved implementation plan requires the pure-domain production scope to include the APP-05 classification command, APP-06 Activity creation/modification and date slicing, APP-07 confirmation and Timeline revision behavior, APP-08 Baseline observation lifecycle, and APP-09 timer start/manual record behavior. Those command paths and their port-backed atomic changes do not exist in the reviewed sources.

This leaves functional requirements and approved traceability cases without an implementation route: `TR-02`, `TR-04` through `TR-07`, `TR-15` through `TR-16`, `TR-23` through `TR-24`, `TR-27` through `TR-30`, and the corresponding atomic-failure cases cannot be executed by the module. The omission is inside the selected pure-domain scope, not deferred Android/DB/UI/backup work. Add domain services with explicit input/state validation and interfaces that request the required whole-state changes atomically; then exercise each approved result through the runner.

## Recovery and Goal ratios discard valid Duration precision

**confirmed** — `MetricsEngine.recoveryRate` constructs `Ratio` from `assignedRecovered.toMillis()` and `saved.savedDuration().toMillis()`. `RecoveryEngine.progress` uses the same conversion for Goal progress. Java `Duration` retains nanoseconds, so these conversions truncate rather than preserve the absolute elapsed durations required by DM-02 and the Java 17 precision decision. For a positive saved duration below one millisecond, the denominator becomes zero and `Ratio` rejects a valid result; for other fractional-millisecond values, the reported raw ratio is understated.

DM-24, DM-25, BR-09-08, and the technology decision require an unrounded domain ratio, with rounding reserved for the presentation boundary. Preserve the exact duration representation in the ratio model and prove it with non-whole-millisecond assigned and saved durations.

## The green verifier does not cover the approved Gate 2 regression set

**confirmed** — `DomainEngineTestRunner` runs 11 named checks. The approved quality design requires the pure-domain cases from BR-T01~T24 and TR-49~TR-62 by category, and the STEP 05 Gate 1 chose that stronger scope. Present coverage does not test complete zero-Waste days, an explicit coverage-gap observation reset, Context multi-evidence collapsing to one decision, Context confirmation replacement failure preservation, App/Activity command validation, timer single-running/start and manual record behavior, same-Goal overlap, or representative-resolution inheritance after re-splitting.

The current partial-coverage check does not demonstrate the required incomplete-gap or observation lifecycle behavior. Add deterministic fixed-`Instant` tests for every missing pure-domain ownership case and keep the runner's non-zero failure propagation as the final Gate 2 execution proof.
