# 상세 비즈니스 규칙

> 이 문서는 requirements.md의 각 FR에 대한 구체적 규칙을 정의합니다.
> 팀원 누구든 이 문서만 보면 코딩할 수 있어야 합니다.

## 1. 앱 사용 데이터 수집 (FR-1)

### 세션 재구성 규칙

| 규칙 ID | 규칙 | 예시 |
|---|---|---|
| S-1 | Foreground 이벤트 → Background 이벤트 = 하나의 세션 | YouTube FG 19:05 → BG 19:55 = 50분 세션 |
| S-2 | Background 없이 다른 앱 FG가 오면 이전 앱 종료 시점 = 새 앱 FG 시점 | YouTube FG 19:05 → Instagram FG 19:55 → YouTube 종료=19:55 |
| S-3 | Screen Off 이벤트 → 현재 앱 세션 종료 | YouTube FG 19:05 → ScreenOff 19:30 = 25분 세션 |
| S-4 | 세션 최소 지속시간 = 5초. 미만은 무시 | 3초 세션 → 버림 |
| S-5 | 같은 앱이 10초 이내 다시 FG → 하나로 병합 | YouTube 50분 → 5초 gap → YouTube 30분 = YouTube 80분 |
| S-6 | 자정(00:00) 넘기는 세션 → 두 날로 분할 | 23:50~00:10 → 23:50~00:00 (10분) + 00:00~00:10 (10분) |

### 수집 주기

- 30분 간격 자동 수집 (WorkManager)
- 앱 실행 시에도 최신 데이터 갱신
- 배터리 소모: 하루 전체의 2% 이하

## 2. 앱 분류 (FR-2)

| 규칙 ID | 규칙 |
|---|---|
| C-1 | 새로 설치된 앱의 기본 분류 = '중립' |

| C-4 | 분류 종류: PRODUCTIVE / LEISURE / WASTE / NEUTRAL |

## 3. Context 분석 (FR-4, FR-5)

### 시간 중첩 판정

| 규칙 ID | 조건 | 결과 |
|---|---|---|
| X-1 | 세션과 활동이 **1분 이상** 겹침 | 중첩으로 판정 |
| X-2 | 중첩 비율 = 겹치는 시간 / 세션 지속시간 | 0.0 ~ 1.0 |
| X-3 | 중첩 비율 **≥ 50%** | Context로 처리 (활동 맥락 적용) |
| X-4 | 중첩 비율 **< 50%** | 앱 기본 분류 적용 |
| X-5 | 여러 활동과 겹칠 때 | 가장 긴 겹침 기준 |

### Context 분류 결정

| 앱 기본 분류 | 활동 유형 | 최종 분류 | 설명 |
|---|---|---|---|
| WASTE | 운동(RUNNING) | **MIXED** | 낭비 제외. 운동 중 시청 |
| WASTE | 공부(STUDY/DEVELOPMENT/READING) | **충돌 → 사용자 확인** | 딴짓인지 강의인지 모름 |
| WASTE | 여가(LEISURE) | **WASTE** | 여가 중 낭비앱 = 여전히 낭비 |
| PRODUCTIVE | 아무거나 | **PRODUCTIVE** | 생산 앱은 유지 |
| NEUTRAL | 아무거나 | **NEUTRAL** | 중립 유지 |
| LEISURE | 아무거나 | **LEISURE** | 여가 유지 |

### 활동 충돌 확인

- 충돌 감지 시 사용자에게 5개 선택지 제시:
  1. 강의/공부 목적 → PRODUCTIVE
  2. 보조적 시청 → MIXED (낭비 제외)
  3. 딴짓 → WASTE
  4. 의도적 휴식 → LEISURE (낭비 제외)
  5. 기타 → NEUTRAL
- 미응답 시 → 앱 기본 분류 적용
- **하루 최대 10회** 질문 제한 (사용자 피로도 방지)

### 사용자 수정

- Timeline에서 분류를 수동 수정 가능
- 수정 시 `userConfirmed = true` → 재계산에서 제외
- 수정하면 낭비시간 즉시 재계산

|---|---|
| W-1 | 낭비시간 = WASTE로 분류된 모든 Context의 세션 duration 합계 |

| W-3 | 일별/주별 합산 제공 |

## 6. 시간 되찾기 (FR-9, FR-10)

| 규칙 ID | 규칙 |
|---|---|
| T-1 | 목표를 선택하고 타이머 시작 |
| T-2 | 앱 벗어나도 백그라운드 동작 (Foreground Service) |
| T-3 | 종료 시 → RecoveredTime 기록 (method=TIMER) |
| T-4 | 취소 시 → 기록 안 함 |
| T-5 | **최소 1분** — 1분 미만은 기록하지 않음 |
| T-6 | 수동 기록도 가능 (method=MANUAL) — 시작/종료 시간 입력 |
| T-7 | 수동 기록 시 Activity도 동시 생성 (Context 분석 연동) |
| T-8 | 목표 최대 10개 |
| T-9 | 회수율 = 되찾은 시간 / 확보시간 × 100 |
| T-10 | 확보시간 ≤ 0이면 회수율 미표시 |
| T-11 | 회수율 100% 초과 가능 |

## 7-1. 연속 사용 감지 및 리프레쉬 (FR-15)

| 규칙 ID | 규칙 |
|---|---|
| R-1 | 낭비 분류된 앱을 **연속 60분 이상** 사용 시 트리거 |
| R-2 | 감지 시 오버레이 팝업으로 경고 표시 ("1시간 넘게 사용 중이에요") |
| R-3 | 팝업에 미니게임 또는 상식 퀴즈 1문제를 표시 |
| R-4 | 퀴즈/미니게임 완료 후 선택지 제시: "계속 사용" / "그만두기" |
| R-5 | "그만두기" 선택 시 홈 화면으로 이동 유도 |
| R-6 | 같은 앱에 대해 **30분마다** 반복 트리거 (60분 후 첫 번째, 이후 30분 간격) |
| R-7 | 미니게임/퀴즈 풀은 사전 정의된 목록에서 랜덤 출제 |
| R-8 | 사용자가 설정에서 이 기능을 ON/OFF 할 수 있음 |

## 7-2. 일일 피드백 문구 (FR-16)

| 규칙 ID | 규칙 |
|---|---|
| F-1 | 비교 기준 = 최근 7일간 일평균 낭비시간 |
| F-2 | 오늘 낭비 < 7일 평균 → 긍정 문구 |
| F-3 | 오늘 낭비 ≥ 7일 평균 → 격려 문구 |
| F-4 | 문구는 사전 정의 풀(긍정 10개+, 격려 10개+)에서 랜덤 선택 |
| F-5 | 같은 문구가 3일 연속 나오지 않도록 히스토리 관리 |
| F-6 | 표시 시점: 자정 직전 또는 앱 첫 실행 시 전날 결과로 |
| F-7 | 홈 대시보드 상단에 카드 형태로 표시 |

### 문구 예시

**긍정:**
- "오늘 평소보다 30분 덜 낭비했어요. 잘하고 있어요!"
- "이 속도면 이번 주 목표 달성 가능해요."
- "어제보다 좋아졌어요. 꾸준함이 핵심이에요."

**격려:**
- "오늘은 좀 많이 썼네요. 내일 다시 도전!"
- "괜찮아요. 인식하는 것 자체가 첫걸음이에요."
- "내일은 30분만 줄여볼까요?"
