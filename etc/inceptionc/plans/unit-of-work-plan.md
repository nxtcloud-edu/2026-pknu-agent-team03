# INCEPTION STEP 07 — 작업 단위 쪼개기 계획

## 1. 단계 실행 판단

- 실행 계획에서 STEP 07 실행이 승인되었다.
- 승인된 25개 유저 스토리와 29개 논리 구성 요소를 한 번에 구현하면 선행 관계와 완료 기준이 불명확해진다.
- 따라서 한 작업 단위를 CONSTRUCTION STEP 05 코드 생성까지 끝낸 뒤 다음 단위로 이동할 수 있도록 순차 작업 단위를 정의한다.

## 2. 입력과 산출물

- 입력: `inception/requirements/requirements.md`
- 입력: `inception/user-stories/stories.md`
- 입력: `inception/plans/execution-plan.md`
- 입력: `inception/application-design/components.md`
- 산출물: `inception/application-design/unit-of-work.md`
- 범위: 작업 단위, 선행 관계, 스토리·요구사항·구성 요소 배정, 단위별 단계 적용, 종료 조건
- 제외: 언어, 프레임워크, 런타임, 데이터베이스 제품, 배포 제품 선택

## 3. 작업 단위가 뜻하는 것

작업 단위 하나는 단순한 기능 목록이 아니다. 다음 다섯 단계를 승인받아 코드까지 끝내는 하나의 구현 묶음이다.

```text
기능 설계 → 비기능 요구 → 비기능 설계 → 필요한 경우 인프라 설계 → 코드 생성
```

예를 들어 `사용 이벤트와 세션`을 하나의 작업 단위로 정하면, 이벤트 수집 규칙과 세션 재구성 규칙을 설계하고, 필요한 품질 조건과 기술 스택을 결정하고, 저장·검증·코드를 완성한 뒤 다음 단위로 넘어간다.

## 4. 승인된 고정 조건

- 마일스톤 순서는 M1 낭비시간 발견 → M2 Baseline·리포트 → M3 목표·시간 회수 → M4 익명 백업·데이터 통제다.
- 모든 작업 단위에서 CONSTRUCTION STEP 01, 02, 03, 05를 실행한다.
- 서버·백업·외부 실행 환경이 포함된 단위에서만 CONSTRUCTION STEP 04 인프라 설계를 실행한다.
- 전체 빌드와 테스트는 모든 작업 단위가 끝난 뒤 CONSTRUCTION STEP 06에서 한 번 실행한다.
- 모든 US-01–US-25는 정확히 하나의 주 구현 단위에 배정한다.
- 기술 스택은 이 단계가 아니라 각 작업 단위의 CONSTRUCTION STEP 02에서 결정한다.

### Q8. 필수 워크플로의 순차 작업 단위 규칙과 4명 병렬 작업 목표를 어떻게 조정할까요?

B) `timeback-mvp` 하나의 큰 작업 단위 안에 기기·도메인·UI·백업·서버 책임 트랙을 두어 네 명의 병렬 참여를 최대화
