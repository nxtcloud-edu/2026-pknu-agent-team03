# INCEPTION STEP 05 — 실행 계획

## 1. 목적

승인된 요구사항과 유저 스토리를 INCEPTION 설계 단계와 CONSTRUCTION 구현 단계로 연결한다. 이 파일은 STEP 05의 계획 파일이자 최종 산출물이며, 게이트 1 승인 후 아래 체크리스트와 실행 순서를 확정한다.

## 2. 입력

- `inception/requirements/requirements.md`
- `inception/user-stories/stories.md`
- Complexity Estimate: `Complex`
- Requirements Depth: `Comprehensive`
- 첫 핵심 여정: 권한 허용 → 이벤트 수집 → Timeline 및 Context 수정 → 낭비시간 확인

## 6. 확정 실행 원칙

- 한 작업 단위를 CONSTRUCTION STEP 05 코드 생성까지 끝낸 뒤 다음 작업 단위로 이동한다.
- 코드 생성 순서는 업무 규칙 → API → 저장 → 화면이며 각 층의 테스트를 같은 단계에서 함께 만든다.
- 현재 문서에서는 언어, 프레임워크, 런타임, 데이터베이스 제품, 배포 제품을 선택하지 않는다.
- 기술 스택은 각 작업 단위의 CONSTRUCTION STEP 02 `tech-stack-decisions.md`에서만 확정한다.
- 서버 백업은 반복 초기화 가능한 격리된 로컬 환경에서 실제 서버를 실행하고 자동 API·통합 테스트로 검증한다.
- Android 14 이상 기기가 작업 환경에 연결되어 있으면 직접 UsageStats 시나리오를 실행하고, 없으면 동일한 수동 체크리스트를 사용자에게 제공한다.
- 실제 기기 시나리오 결과가 기록되기 전에는 NFR-3.3을 완료로 표시하지 않는다.
- 연속 7일 Baseline은 제어 가능한 시간과 고정 테스트 데이터로 자동 검증하고 실제 데이터로 스모크 테스트한다.

## 8. INCEPTION 남은 단계

### STEP 06 애플리케이션 설계

- 입력: `requirements.md`, `stories.md`, 이 `execution-plan.md`
- 계획: `inception/plans/application-design-plan.md`
- 산출물: `inception/application-design/components.md`
- 포함 내용: 구성 요소 책임, 경계, 데이터 흐름, 인터페이스 방향, 오류 흐름, 전체 검증 진입점
- 완료 조건: Android 앱 내부 영역과 익명 백업 서버 영역의 책임이 겹치지 않고 모든 FR/NFR이 하나 이상의 구성 요소에 연결되어야 한다.

### STEP 07 작업 단위 쪼개기

- 입력: `components.md`, `stories.md`, 이 `execution-plan.md`
- 계획: `inception/plans/unit-of-work-plan.md`
- 산출물: `inception/application-design/unit-of-work.md`
- 포함 내용: 순차 작업 단위, 선행 관계, 스토리·요구사항 배정, 단위별 조건 단계 적용 여부
- 완료 조건: 모든 스토리가 정확히 하나의 주 구현 단위에 배정되고, 한 단위씩 STEP 05까지 진행할 수 있는 순서가 정해져야 한다.

| 기기 제조사·상태에 따른 UsageEvent 차이 | 세션 누락 또는 잘못된 종료 시각 | 원본 이벤트를 보존하고 실제 기기 체크리스트와 짝 없는 이벤트 규칙을 검증 |
| 권한 회수 후 오래된 화면 표시 | 사용자가 수집이 계속되는 것으로 오해 | 주요 화면 진입 시 권한 상태를 다시 확인하고 미허용 상태를 명확히 표시 |
| 자정·주간 경계 및 현지 시간 오류 | 일간·주간 합계 불일치 | 제어 시간과 월요일 경계 고정 사례를 자동 테스트 |
| 겹친 활동의 이중 합산 | 낭비시간·목표시간 과대 계산 | 구간 합집합과 대표 목표 규칙을 단위 테스트 |
| Baseline 테스트가 실제 7일에 의존 | 개발과 회귀 테스트 지연 | 제어 가능한 시간과 고정 7일 데이터를 사용 |
| 백업 환경 상태가 테스트마다 달라짐 | 통합 테스트 재현 실패 | 격리 환경을 반복 초기화하고 고정된 테스트 데이터 사용 |
| 익명 데이터 삭제 일부 실패 | 사용자 데이터 잔존 | 모든 저장 경계 삭제를 확인하기 전 완료로 표시하지 않음 |
| 실제 Android 기기 미연결 | NFR-3.3 검증 미완료 | 수동 체크리스트를 제공하고 결과 기록 전까지 해당 항목을 미완료로 유지 |
| 5초 화면 갱신 기준 미달 | NFR-1.1 실패 | 대표 데이터 규모에서 새로고침 시간을 측정하고 병목을 단위 설계로 환류 |

## 13. 최종 완료 정의

- INCEPTION STEP 06·07과 모든 작업 단위의 필수 CONSTRUCTION 단계가 승인 완료되어야 한다.
- 모든 FR/NFR과 US-01–US-25가 설계, 코드, 테스트 중 하나 이상의 증거에 추적되어야 한다.
- 전체 자동 테스트와 격리 로컬 서버 API·통합 테스트가 통과해야 한다.
- 설치 가능한 디버그 빌드와 전체 소스가 제공되어야 한다.
- 실제 Android 14 이상 기기 시나리오는 연결 기기에서 실행하거나 사용자 수동 체크리스트 결과로 기록되어야 한다.
- 자동 테스트 결과, 실제 기기 수동 체크리스트, 앱·서버 실행 방법이 제공되어야 한다.
- 실제 기기 결과가 아직 없으면 그 사실과 미완료 NFR-3.3을 최종 요약에 명시해야 한다.
- 언어·프레임워크·런타임 선택은 이 단계가 아니라 CONSTRUCTION STEP 02에서만 이루어져야 한다.
