# TimeBack 애플리케이션 구성 요소 설계

## 1. 설계 결정

- Android 앱은 화면이 아니라 도메인 능력별 구성 요소로 나눈다.
- 기기 데이터가 기준 데이터이며 서버에는 백업 사본만 둔다.
- 로컬 데이터가 변경되면 자동으로 백업을 요청하고, 실패한 변경은 기기에 보관했다가 앱 시작 시 다시 시도한다.
- 네트워크가 없어도 수집·분석·목표·리포트 기능을 계속 제공하고 백업만 대기한다.
- 익명 사용자 식별자는 기기 하드웨어 정보에서 변환한다.
- 원본 하드웨어 값은 저장하거나 서버로 보내지 않고 변환된 식별자만 사용한다.
- 전체 삭제는 기기와 서버 삭제를 하나의 작업으로 추적하며 양쪽이 끝난 뒤에만 완료로 표시한다.
- 주요 화면은 책임, 사용 도메인, 상태, 사용자 동작, 오류·빈 상태까지 설계한다.
- 언어, 프레임워크, 런타임, 데이터베이스 제품, 배포 제품은 선택하지 않는다.

## 2. 전체 경계

```text
┌──────────────────── Android 운영체제 경계 ────────────────────┐
│ Usage Access 권한 · UsageStats 이벤트 · 화면 상태 · 현지 시간 │
│ 기기 하드웨어 식별원                                         │
└──────────────────────────┬─────────────────────────────────────┘
                           │ 운영체제 경계 인터페이스
┌──────────────────────────▼─────────────────────────────────────┐
│                       Android 앱                               │
│                                                               │
│ 권한·수집 → 세션 → 앱 분류·활동 → Context → 시간 지표        │
│                                         ↘ 목표·시간 회수       │
│                                                ↓              │
│                    Timeline·대시보드·리포트·설정 화면          │
│                                                ↓              │
│                 기기 기준 저장소 → 변경 기록 → 백업 조정      │
└──────────────────────────┬─────────────────────────────────────┘
                           │ 익명 식별자 + 백업 변경
┌──────────────────────────▼─────────────────────────────────────┐
│                    익명 백업 서버 경계                         │
│          백업 요청 처리 · 백업 사본 · 보관·삭제 처리          │
└────────────────────────────────────────────────────────────────┘
```

## 3. Android 운영체제 경계 구성 요소

| ID | 구성 요소 | 책임 | 제공하는 논리 인터페이스 |
|---|---|---|---|
| OS-01 | Usage Access Gateway | 권한 상태 확인과 설정 화면 이동을 Android 운영체제 경계로 격리 | 권한 상태 조회, 권한 설정 열기 |
| OS-02 | Usage Event Source | 허용된 기간의 패키지명, 이벤트 종류, 발생 시각 조회 | 기간별 UsageEvent 조회 |
| OS-03 | Screen State Source | 짝 없는 세션을 닫는 데 필요한 화면 종료 시각 제공 | 화면 종료 이벤트 조회 |
| OS-04 | Device Identity Source | 익명 식별자 생성에 사용할 기기 하드웨어 식별원 제공 | 안정적인 기기 식별원 읽기 |
| OS-05 | Time Source | 현지 시각, 자정, 월요일 경계와 테스트용 제어 시간 제공 | 현재 시각, 현지 시간대, 기간 경계 |

### 경계 규칙

- OS-01이 허용 상태를 반환하지 않으면 OS-02를 호출하지 않는다.
- OS-02는 화면 내용, 앱 내부 콘텐츠, 위치, 자동 오프라인 활동을 반환하지 않는다.
- OS-04에서 읽은 원본 하드웨어 값은 기기 저장소나 서버 요청에 직접 포함하지 않는다.
- OS-05를 통해서만 시간 계산 기준을 얻어 7일 Baseline과 경계 테스트를 제어할 수 있게 한다.

## 5. 서버 구성 요소

| ID | 구성 요소 | 책임 | 저장 범위 | 금지 사항 |
|---|---|---|---|---|
| SRV-01 | Anonymous Backup Boundary | 익명 식별자별 백업 변경 수신, 성공·실패 응답, 전체 삭제 요청 수신 | 요청 처리 상태 | 로그인 계정 요구, 기기 업무 규칙 재판정 |
| SRV-02 | Backup Copy Store | 기기 기준 데이터의 백업 사본 보관과 조회 | 변환된 익명 식별자 및 백업 데이터 | 원본 하드웨어 값 저장, 서버를 기준 데이터로 취급 |
| SRV-03 | Retention & Deletion Executor | 사용자 보관 선택 적용, 익명 식별자별 전체 백업 삭제 | 보관·삭제 실행 상태 | 기기 삭제 완료를 대신 확정 |

### 서버 경계 규칙

- 서버는 Context, Baseline, 회수율을 독립적으로 다시 판정하여 기기 값을 덮어쓰지 않는다.
- 서버는 변환된 익명 식별자를 불투명한 데이터 묶음 키로만 사용한다.
- 백업 실패는 기기 데이터 저장 성공을 되돌리지 않는다.
- 전체 삭제는 SRV-03의 삭제 완료가 확인될 때까지 기기 삭제 조정자에 성공으로 응답하지 않는다.

## 7. 화면 구성 요소

### UI-01. 권한·초기 진입

- 책임: Usage Access 필요성, 현재 권한 상태, 설정 이동, 주요 화면 접근 제어
- 사용하는 구성 요소: APP-01, APP-02
- 상태: 권한 확인 중, 권한 없음, 권한 허용됨, 권한 회수됨, 식별자 생성 실패
- 사용자 동작: 권한 설정 열기, 권한 상태 다시 확인
- 오류·빈 상태: 권한 미허용이면 주요 화면을 표시하지 않고 안내 유지

### UI-02. 홈 대시보드

- 책임: 오늘 낭비시간, Baseline 대비 변화, 확보·회수시간, 회수율, 목표 진행도 표시
- 사용하는 구성 요소: APP-08, APP-09, APP-10
- 상태: Baseline 관찰 중, 지표 표시, 새로고침 중, 데이터 없음, 계산 오류
- 사용자 동작: 새로고침, Timeline·목표·리포트 이동
- 오류·빈 상태: Baseline 미완료이면 확보시간·회수율 대신 남은 관찰 기간 표시

### UI-03. Timeline

- 책임: AppSession·Activity·Context 시간순 표시, 충돌 확인, Context 수정
- 사용하는 구성 요소: APP-04, APP-06, APP-07, APP-10
- 상태: 로딩, 데이터 없음, 정상 Timeline, MIXED 확인 대기, 수정 중, 오류
- 사용자 동작: 날짜 변경, Activity 추가·수정, Context 확인·수정, 새로고침
- 오류·빈 상태: 수집 이벤트가 없으면 빈 Timeline과 수집 조건 안내

### UI-04. 앱 관리

- 책임: 설치 앱 목록과 기본 분류 표시·수정
- 사용하는 구성 요소: APP-05
- 상태: 앱 목록 로딩, 정상 목록, 미분류 앱 있음, 목록 없음, 저장 오류
- 사용자 동작: 앱 선택, 기본 분류 변경
- 오류·빈 상태: 목록을 읽지 못하면 기존 저장 분류를 훼손하지 않고 오류 표시

### UI-05. 시간 되찾기

- 책임: 목표 선택, 타이머 시작·완료, 활동 직접 기록
- 사용하는 구성 요소: APP-09
- 상태: 목표 없음, 타이머 대기, 타이머 실행, 완료, 직접 입력, 중첩 확인, 오류
- 사용자 동작: 목표 선택, 시작, 완료, 직접 기록, 대표 목표 선택
- 오류·빈 상태: 목표가 없으면 목표 생성 이동 제공

### UI-06. 목표

- 책임: 목표 생성, 목표시간, 누적시간, 진행률 표시
- 사용하는 구성 요소: APP-09, APP-10
- 상태: 목표 없음, 목표 목록, 목표 상세, 저장 중, 오류
- 사용자 동작: 생성, 조회, 시간 기록으로 이동
- 오류·빈 상태: 목표 없음 상태에서 첫 목표 생성 동작 제공

### UI-07. 리포트

- 책임: 일·주·월 통계, Baseline 비교, 목표별 시간 표시
- 사용하는 구성 요소: APP-08, APP-09, APP-10
- 상태: 기간 선택, Baseline 미완료, 정상 리포트, 데이터 없음, 오류
- 사용자 동작: 기간 변경, 목표별 상세 조회
- 오류·빈 상태: 선택 기간에 데이터가 없으면 0과 미수집을 구분해 표시

### UI-08. 데이터 관리

- 책임: 익명 백업 상태, 보관 기간 선택, 전체 삭제 진행 상태 표시
- 사용하는 구성 요소: APP-02, APP-12, APP-13
- 상태: 백업 완료, 백업 대기, 백업 실패, 오프라인, 삭제 확인, 삭제 진행, 부분 실패, 삭제 완료
- 사용자 동작: 백업 상태 확인, 보관 기간 변경, 전체 삭제 요청·확정
- 오류·빈 상태: 기기와 서버 중 하나라도 삭제가 끝나지 않으면 전체 완료로 표시하지 않음

## 11. 품질 요구 반영

### 성능

- Timeline과 대시보드 조회는 서버 백업 완료를 기다리지 않는다.
- APP-10은 기기 기준 데이터에서 필요한 기간만 조회해 화면 새로고침 5초 기준을 검증할 수 있게 한다.
- 백업과 삭제 상태 조회는 핵심 시간 계산 경로와 분리한다.

### 정확성

- APP-04, APP-06, APP-07, APP-09는 모두 OS-05의 동일한 시간·기간 계약을 사용한다.
- 중첩 계산은 실제 구간 합집합을 기준으로 하며 화면에서 별도 합산하지 않는다.
- Context 수정 후 APP-08–APP-10이 같은 최종 Context를 사용한다.

### 테스트 가능성

- OS-02–OS-05는 고정 이벤트, 화면 종료, 하드웨어 식별원, 제어 시간으로 대체 가능한 경계다.
- APP-04, APP-07, APP-08, APP-09는 화면과 저장 제품 없이 규칙을 검증할 수 있는 책임을 가진다.
- APP-12와 SRV-01 경계는 성공, 네트워크 실패, 재시도를 반복 검증할 수 있어야 한다.

### 보안·개인정보

- 권한이 없으면 UsageEvent를 수집하지 않는다.
- 원본 하드웨어 값은 APP-02 변환 경계 밖으로 나가지 않는다.
- 서버는 로그인 계정이나 원본 하드웨어 값 없이 변환된 익명 식별자만 사용한다.
- 화면 내용, YouTube 내부 콘텐츠, 위치, 자동 오프라인 활동은 어떤 구성 요소도 수집하지 않는다.

### 유지보수

- UsageEvent, AppSession, Activity, Context, Goal, RecoveredTime의 저장 책임을 구분한다.
- 앱 기본 분류와 사용자 확정 Context를 별도 데이터로 유지한다.
- UI는 도메인 계산을 구현하지 않고 APP-03–APP-13의 결과와 작업만 사용한다.

## 13. 논리 검증 진입점

정확한 실행 명령은 기술 스택을 선택하는 CONSTRUCTION STEP 02에서 연결한다. 이 단계에서는 다음 검증 책임 이름을 고정한다.

| 논리 이름 | 검증 범위 |
|---|---|
| `verify-domain` | 세션, 중첩, Context, Baseline, 확보·회수시간 규칙 |
| `verify-data` | 기기 저장 생성·수정·삭제·재계산 |
| `verify-device` | Android 14 이상 권한·UsageEvent 실제 기기 시나리오 |
| `verify-backup` | 익명 백업 성공·실패·재시도·보관·삭제 |
| `verify-ui` | 주요 화면과 도메인·저장 통합 흐름 |
| `build-debug` | 설치 가능한 디버그 산출물 생성 |
| `verify-all` | 앱·서버 전체 빌드와 자동 검증 |

## 14. 후속 단계 전달 사항

- STEP 07은 APP-03–APP-13과 SRV-01–SRV-03의 책임을 순차 작업 단위로 묶는다.
- M1부터 M4 순서를 유지하고 한 단위를 코드 생성까지 끝낸 뒤 다음 단위로 이동한다.
- 하드웨어 기반 익명 식별자의 안정성·접근 가능성·개인정보 영향은 관련 작업 단위의 CONSTRUCTION STEP 02에서 필수 검증한다.
- 실제 하드웨어 식별원이 요구한 안정성을 제공하지 못하면 임의 대체하지 않고 요구사항 변경 승인을 요청한다.
- UI 상세 상태는 각 작업 단위의 `frontend-components.md`에서 이 문서와 모순 없이 구체화한다.
