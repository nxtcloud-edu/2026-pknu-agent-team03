# `timeback-mvp` CP-0 공통 업무 규칙

## 1. 문서 상태와 역할

- 단계: CONSTRUCTION STEP 01 기능 설계
- 범위: CP-0 공통작업
- 상태: 게이트 2 승인 전 후보
- 역할: 네 책임 트랙이 독자적으로 바꿀 수 없는 공통 불변조건의 기준

이 문서는 구현 알고리즘과 제품별 예외 처리를 정하지 않는다. 수치는 승인된 요구사항에 있는 경우에만 인용하며, 새 임계값은 만들지 않는다.

## 2. 규칙 적용 우선순위

1. 승인된 `requirements.md`와 `stories.md`
2. 최종 `unit-of-work.md`의 소유권과 트랙 배정
3. `components.md`의 구성 요소·데이터 경계
4. 이 문서의 CP-0 공통 규칙

규칙이 상위 문서와 다르게 해석되면 상위 문서를 적용하고 현재 활성 단계의 승인을 받아 이 문서를 수정한다.

## 10. 오류 상태 우선 해석

한 흐름에서 여러 상태가 함께 관찰되면 각 책임 경계를 보존한다.

| 함께 발생한 상태 | 공통 해석 |
|---|---|
| 권한 미허용 + 기존 로컬 데이터 있음 | 주요 화면 접근 제한을 유지하고 기존 데이터를 삭제하지 않음 |
| 로컬 저장 성공 + 백업 실패 | 로컬 기능 성공, 백업 대기 |
| Baseline 관찰 중 + 기간 데이터 없음 | 관찰 상태와 데이터 없음 원인을 구분해 표시 |
| Context 확인 필요 + 계산 조회 요청 | 미확정 MIXED를 유지하고 확정 결과로 꾸미지 않음 |
| 기기 삭제 성공 + 서버 삭제 실패 | 전체 삭제 부분 실패, 완료 아님 |

- 실제 하드웨어 식별원의 접근 가능성·안정성·개인정보 검증

이 항목들은 공통 계약의 현재 의미를 바꾸지 않는 범위에서만 트랙 상세 설계가 구체화한다.

## Track Rules — device-data

이 섹션은 `track-device-data`가 소유한 상세 규칙이다. `DataOwnerScope`, `ReplacePeriodRecords`, 변경 커서는 CT-03 변경 제안이며 공통 계약 승인 전에는 다른 트랙의 확정 규칙이 아니다.

| 규칙 ID | 상세 규칙 | 영향 계약 | 추적 |
