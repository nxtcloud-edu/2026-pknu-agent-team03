# TimeBack 웹 대시보드 안정화·UI 개선 계획

## 1. 목표

- 기존 Spring Boot `demo` 프로필과 `/demo-api/**` 계약을 유지한다.
- 데스크톱의 과도한 여백과 모바일 내비게이션 오버플로를 해소한다.
- API 지연·실패·빈 데이터가 흰 화면이나 처리되지 않은 Promise로 끝나지 않게 한다.
- Timeline, Goal, Report, Settings의 합성 데모 기능을 더 명확하고 접근 가능하게 제공한다.
- 실제 Android·Room·CT-05 데이터로 오인되지 않는 표시와 삭제 경계를 유지한다.

## 2. 진단 결과

| 항목 | 현재 상태 | 보정 방향 |
|---|---|---|
| 데스크톱 레이아웃 | 최대 폭 680px 단일 열이라 넓은 화면에서 정보 밀도가 낮음 | 1120px 반응형 그리드와 요약·차트·Timeline 2열 구성 |
| 모바일 내비게이션 | 6개 탭이 한 줄에 고정되어 작은 화면에서 압축·넘침 가능 | 가로 스크롤 가능한 탭과 44px 이상 터치 영역 |
| 초기 렌더 | 모든 페이지 API를 동시에 호출하고 로딩 상태가 없음 | 현재 페이지 중심 로딩, 공통 skeleton·재시도 제공 |
| API 오류 | JSON 응답을 전제하며 오류가 사용자에게 표시되지 않음 | timeout·비 JSON·HTTP 오류를 통합 처리하고 오류 배너·toast 표시 |
| 빈 데이터 | 삭제 뒤 Timeline·Goal·앱 화면이 빈 카드로 남음 | 화면별 empty state와 데모 데이터 복원 동작 제공 |
| 입력 | 목표 시간 범위와 활동 설명 오류가 서버 응답 뒤에만 드러남 | 클라이언트 선검증, 버튼 진행 상태, 성공·실패 toast |
| 접근성 | Timeline 행이 `div onclick`, modal dialog 속성·focus 관리 없음 | 실제 button, ARIA tab/dialog/live region, 키보드·focus 복원 |
| 실행 의존성 | 외부 Pretendard CDN을 요청함 | 시스템 폰트만 사용해 오프라인 JAR 단독 실행 보장 |

## 3. 구현 순서

- [x] HTML을 skip link, 상태 배너, 접근 가능한 탭, toast, dialog 구조로 보강한다.
- [x] CSS를 1120px 데스크톱 그리드와 태블릿·모바일 breakpoints로 재구성한다.
- [x] JavaScript를 단일 상태·페이지별 renderer·공통 loading/error/empty 처리로 정리한다.
- [x] Goal 추가·기록, Timeline 분류, 보관 기간, 합성 동기화의 진행·결과 상태를 표시한다.
- [x] 합성 데이터 삭제 후 `/demo-api/reset`으로 시연 데이터를 복원할 수 있게 한다.
- [x] 기본 프로필 데모 API 차단과 실제 `/api/**` 백업 계약은 변경하지 않는다.
- [x] Spring 통합 테스트, 전체 `verifyAll`, Android clean build·lint를 통과시킨다.
- [x] 브라우저에서 데스크톱·모바일 화면, 탭 이동, 입력, 오류·빈 상태를 검증한다.

## 4. 완료 조건

- 데스크톱과 390px 모바일에서 가로 페이지 스크롤 없이 핵심 화면을 사용할 수 있다.
- API 실패 시 오류 메시지와 재시도 동작이 보이며 콘솔에 처리되지 않은 오류가 남지 않는다.
- 삭제 뒤 모든 합성 화면에 빈 상태가 표시되고 사용자가 데모 데이터를 복원할 수 있다.
- Timeline·Goal·Settings의 주요 동작이 키보드와 마우스로 동작한다.
- 외부 정적 리소스 없이 실행 JAR 하나로 화면이 렌더링된다.
- 기존 92개 회귀와 추가한 대시보드 계약 검증이 모두 통과한다.
