# CONSTRUCTION STEP 01 — `timeback-mvp` 기능 설계 공통작업 계획

## 1. 현재 위치와 목적

- 공식 작업 단위는 `timeback-mvp` 하나다.
- CONSTRUCTION STEP 01 기능 설계를 시작한다.
- 이번 승인 범위는 네 책임 트랙이 병렬 작업을 시작하기 전에 함께 고정해야 하는 CP-0 공통 계약 CT-01–CT-06까지다.
- 공통작업은 별도 작업 단위나 별도 `shared-contracts` 폴더로 만들지 않고 STEP 01의 공식 산출물 네 개에 나눠 기록한다.
- 공통작업 결과가 승인되어도 STEP 01 전체를 완료 처리하지 않는다. 상태는 `진행 중 · CP-0 공통작업 완료`로 남기고 트랙별 상세 작업 직전에 멈춘다.

## 2. 사용자 지정 중지 경계

이번에 진행하는 범위:

- CT-01–CT-06의 제공자·소비자·입력·출력·상태·오류·불변조건
- 네 트랙이 같은 의미로 사용할 논리 엔터티와 시간 구간
- 저장·변경 통지·백업·삭제의 공통 상태 계약
- UI-01–UI-08이 사용할 사용자 작업·조회 결과·화면 상태 계약
- 실제 의존 대상이 없어도 시작할 수 있는 고정 예시와 테스트 대역 계약
- 계약 변경 절차, 소유권, 추적표, 병렬 시작 준비 판정

이번에 진행하지 않는 범위:

- `track-device-data`, `track-domain-engine`, `track-ui`, `track-backup-server`의 개별 상세 작업
- 언어·프레임워크·런타임·데이터베이스·통신·배포 제품 선택
- CONSTRUCTION STEP 02–04의 품질·기술·인프라 설계
- API 경로, 저장 스키마, 화면 구현 코드, 서버 코드
- 워크스페이스 루트 `src/` 생성 또는 수정
- 네 트랙의 실제 병렬 실행

## 3. 고정 입력과 우선순위

| 순위 | 입력 | 이번 단계에서 고정하는 것 |
|---:|---|---|
| 1 | `inception/requirements/requirements.md` | FR/NFR 범위와 승인된 수치·제약 |
| 2 | `inception/user-stories/stories.md` | US-01–US-25의 사용자 결과와 인수 조건 |
| 3 | `inception/application-design/unit-of-work.md` | `timeback-mvp` 단일 작업 단위, 네 책임 트랙, CT-01–CT-06 소유 방향 |
| 4 | `inception/application-design/components.md` | OS·APP·SRV·UI 경계, 데이터 소유권, 논리 필드, 사용자 흐름 |

- 작업 단위 수와 책임 트랙 배정은 STEP 07 최종 `unit-of-work.md`를 기준으로 한다.
- 공통 계약은 승인된 요구사항과 스토리를 구체화할 뿐 새 기능이나 새 수치를 만들지 않는다.
- 충돌이 발견되면 임의로 선택하지 않고 해당 항목을 미확정으로 표시해 승인을 요청한다.

## 6. 계약별 최소 작성 형식

각 CT 계약은 아래 항목을 빠짐없이 가진다.

| 항목 | 내용 |
|---|---|
| 목적 | 이 계약이 분리하는 책임과 해결하는 협업 문제 |
| 기준 정의 위치 | 네 공식 산출물 중 해당 계약의 기준 파일 |
| 제공자·소비자 | 값을 만드는 트랙과 사용하는 트랙 |
| 입력·출력 | 논리 필드와 값 없음·미완료 상태 |
| 명령·조회 | 상태를 바꾸는 작업과 읽기 전용 결과 구분 |
| 성공·실패 | 정상, 빈 결과, 거부, 재시도 가능 실패, 완료 조건 |
| 불변조건 | 트랙이 독자적으로 바꿀 수 없는 공통 규칙 |
| 테스트 대역 | 실제 의존 대상 전 사용할 가짜 입력·응답 |
| 추적 | 관련 요구사항, 스토리, 구성 요소 |
| 변경 영향 | 수정 시 함께 확인할 트랙과 계약 |

## 7. CP-0 완료 조건

- CT-01–CT-06이 §6의 최소 작성 형식을 충족한다.
- 같은 필드·상태·오류가 문서마다 다른 뜻으로 정의되지 않는다.
- 모든 계약에 제공자와 소비자가 있고, 네 트랙이 필요한 입력을 실제 구현 없이 얻을 수 있다.
- UI는 도메인 계산을 복제하지 않고, 서버는 기기 도메인 값을 다시 판정하지 않는다.
- 백업 실패가 로컬 저장을 되돌리지 않고 전체 삭제는 기기·서버 양쪽 완료 뒤에만 완료된다.
- 공통 예시가 승인된 요구사항의 수치와 범위만 사용한다.
- 네 트랙의 병렬 시작 준비 판정이 모두 `준비됨` 또는 명시적 미해결 항목으로 표시된다.
- 이번 범위의 체크리스트가 모두 완료되고 게이트 2 결과 승인을 받는다.

## 8. CP-0 이후 상태

- `timeback-mvp`의 CONSTRUCTION STEP 01은 완료가 아니라 `진행 중 · CP-0 공통작업 완료`다.
- 다음 작업은 네 책임 트랙이 이 공통 계약을 기준으로 맡은 상세 기능 설계를 진행하는 것이다.
- 사용자가 별도로 진행을 요청하기 전에는 트랙별 작업과 후속 STEP을 시작하지 않는다.
- 공통 계약을 바꿔야 하면 영향표를 먼저 작성하고 조용히 변경하지 않는다.

## 9. 확인 질문

추가 질문 없음. 사용자가 진행 범위를 “병렬작업 전 공통작업 부분까지”로 명시했고, 승인된 `unit-of-work.md`가 이를 CP-0 및 CT-01–CT-06으로 정의한다.
