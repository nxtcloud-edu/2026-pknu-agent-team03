# TimeBack 프로젝트 원칙

## 제품 목적

TimeBack은 Android 사용 이벤트와 사용자가 기록한 실제 활동의 시간 맥락을 결합해, 사용자가 원하지 않았던 낭비시간을 찾고 그 시간을 목표 활동으로 전환하도록 돕는다.

핵심 흐름은 다음과 같다.

`사용 이벤트 수집 → AppSession 재구성 → Activity 중첩 분석 → Context 판정 → 낭비시간 계산 → Baseline 비교 → 확보시간 → 목표 활동 → 되찾은 시간`

## 핵심 용어

- **Waste Time**: 최종 Context가 `WASTE`로 확정된 실제 시간 구간의 합계
- **Baseline**: 초기 유효 측정 기간의 사용자별 평소 낭비시간
- **Saved Time**: Baseline 대비 감소한 낭비시간
- **Recovered Time**: 사용자가 목표 활동에 실제 투자한 것으로 인정된 시간
- **Recovery Rate**: Saved Time 중 Recovered Time으로 전환한 비율. 0·초과 값 정책은 확정 요구사항을 따른다.

## 제품 판단 원칙

1. 앱 이름만으로 시간의 가치를 확정하지 않는다. 앱 기본 분류는 Default일 뿐이다.
2. 시간, 앱, 실제 활동, 사용자 확인을 결합해 Context를 판정한다.
3. 명시적인 사용자 확인과 Timeline 수정은 기본 분류와 자동 판정보다 우선한다.
4. 같은 실제 시간은 여러 의미를 가질 수 있지만 총 경과시간보다 크게 합산하지 않는다.
5. 자동 판정의 이유와 수정 방법을 사용자에게 설명할 수 있어야 한다.
6. 추천은 비난·강제가 아니라 선택 가능한 작은 행동 변화로 제시한다.

## MVP 경계

MVP에는 Android UsageStats 수집, 세션화, Timeline, 앱 기본 분류, 활동 직접 기록, Context 판정·수정, 낭비/Baseline/확보 계산, 목표, 타이머, 되찾은 시간, 주간 리포트를 포함한다.

다음은 MVP에서 제외한다.

- iOS 완전 지원
- YouTube 내부 콘텐츠와 Shorts 자동 판별
- 화면 내용 감시와 위치 기반 행동 추적
- 모든 오프라인 활동 자동 감지
- 반복 Context 자동 인식, 개인화 추천, 패턴 분석, AI 설명
- 알림, 앱 제한, Health Connect, 캘린더 연동

MVP 제외 기능을 구현에 섞지 않는다. 변경이 필요하면 먼저 `spec.md` 원문 추가와 요구사항 승인을 거친다.
