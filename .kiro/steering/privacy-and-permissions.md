# 개인정보 및 Android 권한 규칙

TimeBack의 앱 사용 기록, 활동, 목표, 시간 패턴은 민감한 행동 데이터로 취급한다.

## 최소 수집

- 기능에 필요한 package name, event type, timestamp만 우선 수집한다.
- 화면 내용, 입력 내용, 위치, YouTube 내부 콘텐츠를 수집하거나 추론하지 않는다.
- 원본 UsageEvent 보관이 필요한 기간과 파생 데이터만 남길 수 있는지 검토한다.
- 로그, 분석 SDK, 오류 보고에 상세 앱·활동·시간 패턴을 기본 포함하지 않는다.

## 권한

- Usage Access가 일반 런타임 권한이 아니라 설정 화면에서 사용자가 허용하는 특수 접근임을 UI에서 설명한다.
- 권한 요청 전 수집 목적, 사용 범위, 제한 기능을 설명한다.
- 미부여·철회·설정 변경 상태를 처리하며 앱이 비정상 종료되지 않아야 한다.
- Manifest에 권한이나 exported 컴포넌트를 추가할 때 필요성, 공격 표면, 대안을 검토한다.

## 저장과 전송

- 온디바이스 처리를 기본값으로 한다.
- 외부 전송, 계정 동기화, 백업을 추가하기 전에 목적, 최소 필드, 암호화, 보존기간, 삭제, 동의를 요구사항으로 확정한다.
- 사용자가 자신의 사용 기록과 파생 Context를 삭제·초기화할 수 있는 정책을 설계한다.
- 사용자 식별자가 필요하지 않은 로컬 MVP에는 불필요한 영구 식별자를 만들지 않는다.

## 변경 검토

다음 변경은 구현 전에 `timeback-privacy-review` Skill을 적용한다.

- `AndroidManifest.xml` 권한/컴포넌트 변경
- UsageStats 수집 범위 또는 보존기간 확대
- 데이터베이스 스키마에 민감 필드 추가
- 네트워크, 분석 SDK, 크래시 리포터, 백업 도입
- 내보내기·공유·동기화 기능 추가
