# TimeBack AI-DLC 운영 규칙

## 근거와 승인

1. 사용자 요구 원문은 루트 `spec.md` 아래에 append-only로 보존한다. 요약·수정·재정렬하지 않는다.
2. `requirements.md`는 `spec.md`에 확인된 내용만 정리한다. 미확정 사항을 추정해 FR로 만들지 않는다.
3. 단계 산출물은 `aidlc-docs/`의 지정 폴더에 두고 실행 코드는 루트 `src/` 또는 Android 모듈 아래에 둔다.
4. 요구사항 STEP 03과 게이트가 완료되기 전에는 애플리케이션 구현 코드를 만들지 않는다.
5. 각 단계는 `계획/질문 → 게이트 1 → 생성 → 게이트 2` 순서를 지킨다.
6. 조건 단계를 생략할 때는 사유를 기록하고 동의를 받는다.

## 기록 보호

- `spec.md`, `aidlc-docs/audit.md`, `aidlc-docs/mistakes.md`는 기존 내용을 덮어쓰거나 삭제하지 않는다.
- 상태는 `aidlc-state.md`, 이력은 `audit.md`, 수정 요청·절차 위반은 `mistakes.md`에 기록한다.
- 게이트 선택지는 `1) 수정 요청`, `2) 다음 단계로` 두 개만 사용한다.
- 원문이 손상되거나 잘렸다면 그 사실을 기록하고 누락 내용을 추정하지 않는다.

## 설계와 구현

- 기술 스택은 Construction의 작업 단위별 `nfr-requirements/tech-stack-decisions.md`에서 결정한다.
- Inception에서는 요구, 논리적 책임, 의존성, 작업 순서까지만 정한다.
- `unit-of-work.md`에 확정한 한 단위를 기능 설계부터 코드 생성까지 끝낸 뒤 다음 단위로 이동한다.
- 실제 코드는 문서 폴더에 넣지 않는다. `construction/{unit}/code/`에는 변경 요약만 기록한다.
- 각 변경은 관련 FR/NFR, 설계 근거, 검증 결과로 추적 가능해야 한다.

## 검증

완료를 주장하기 전에 요청의 성공 조건과 실제 파일·명령 결과를 대조한다. 명령의 종료 코드만으로 제품 동작을 확정하지 않는다.
