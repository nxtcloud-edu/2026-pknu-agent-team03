# TimeBack 릴리스 준비 Skill

## 진입 조건

- `timeback-mvp` Construction STEP 01–05의 Gate 2 승인과 STEP 06 진입 상태가 audit/state에 있어야 한다.
- 승인된 기술 스택 문서에 실제 build·verify 명령이 연결되어 있어야 한다.
- 조건이 없으면 릴리스 작업을 진행하지 않고 누락 근거를 보고한다.

## 절차

1. 릴리스 범위와 관련 FR/NFR, 버전, 변경 목록을 확인한다.
2. 승인된 `build-debug` 또는 릴리스 빌드와 `verify-all` 실제 명령을 실행한다.
3. 시간 도메인, 개인정보, 권한, 백업·삭제, 실제 기기 검증 증거를 확인한다.
4. 비밀, 서명 파일, 사용자 행동 데이터, 로컬 DB가 산출물이나 Git 변경에 포함되지 않았는지 확인한다.
5. 설치 산출물의 경로·해시·빌드 환경과 미검증 항목을 기록한다.
6. 자동 commit, tag, push, 배포는 하지 않고 각각 명시적 사용자 승인을 받는다.

## 완료 기준

종료 코드뿐 아니라 요청된 산출물의 존재, 설치 가능성, 검증 결과, 추적성, 잔여 위험을 대조한다. 실제 기기 검증이 없으면 릴리스 완료로 단정하지 않는다.
