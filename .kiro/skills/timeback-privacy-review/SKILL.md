# TimeBack 개인정보 검토 Skill

## 목적

사용자의 앱 사용 습관과 활동 패턴이 불필요하게 수집·보존·노출되는 것을 방지하고 변경 전에 의사결정 근거를 남긴다.

## 반드시 적용할 변경

- UsageStats 수집 필드·기간 확대
- Android 권한 또는 exported 컴포넌트 변경
- DB 민감 필드와 마이그레이션 추가
- 네트워크, 계정, 동기화, 백업, 내보내기 도입
- 분석 SDK, 광고 SDK, 크래시 리포터 추가
- 로그와 디버그 덤프 변경

## 절차

1. 변경 목적과 연결된 FR/NFR을 찾는다.
2. 데이터 흐름을 `수집 → 변환 → 저장 → 사용 → 전송 → 삭제`로 그린다.
3. 필드마다 필요성, 민감도, 보존기간, 접근 주체를 기록한다.
4. 더 적은 데이터나 파생 데이터만으로 목적을 달성할 수 있는지 검토한다.
5. 권한 미부여·철회·데이터 삭제 시 동작을 확인한다.
6. 로컬 저장, 백업, 로그, 외부 SDK, 네트워크 노출을 확인한다.
7. 위협 시나리오를 검토한다.
   - 다른 앱/컴포넌트의 무단 접근
   - 백업·로그·오류 보고를 통한 노출
   - 계정 혼동 또는 기기 공유
   - 원본 이벤트의 과도한 장기 보관
8. 외부 전송이 새로 생기면 자동 진행하지 말고 명시적 승인을 요청한다.
9. 검토 결과와 잔여 위험을 설계 또는 결정 문서에 남긴다.

## 절대 경계

- 화면 내용 감시 금지
- 위치 기반 행동 추적 금지
- YouTube 내부 콘텐츠/Shorts 자동 판별 금지
- 사용자의 상세 행동 데이터를 제3자 엔드포인트로 전송하지 않음
- 권한을 기능 가치보다 과도하게 요청하지 않음

## 출력

- 데이터 흐름과 필드 목록
- 필요/삭제/축소 결정
- 권한 및 동의 변화
- 저장·보존·삭제 정책
- 외부 전송 여부
- 위험, 완화책, 승인 필요 항목

`references/privacy-checklist.md`로 누락을 확인한다.
